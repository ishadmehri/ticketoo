# Ticketoo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Ticketoo WordPress support-ticket plugin (custom tables, REST API, shortcodes/blocks, wp-admin panel, emails, auto-close) per the approved spec, with tests and WPCS-clean code.

**Architecture:** Custom DB tables (`ticketoo_*`) + repository classes; one REST namespace `ticketoo/v1` serving both the front end and the custom admin panel; server-rendered shortcodes enhanced by vanilla JS; no build step and no runtime Composer dependencies.

**Tech Stack:** PHP 8.0+, WordPress 6.4+, vanilla JS, PHPUnit via `wp-env` (Docker), PHPCS + WPCS inside the wp-env `cli` container.

**Spec:** `docs/specs/2026-09-28-support-tickets-design.md` (this plan argues from the spec; executors read both. ADRs in `docs/ADR/`.)

## Global Constraints

- Target: WordPress 6.4+, PHP 8.0+ (container `phpVersion` pinned to `"8.0"` in `.wp-env.json`).
- Naming: namespace `Ticketoo\`; prefixes `ticketoo_` (functions/options/caps), `ticketoo-` (handles/classes in JS/CSS), `TICKETOO_` (constants); tables `{$wpdb->prefix}ticketoo_*`.
- Text domain `ticketoo`; shortcode `[ticketoo]`; menu slug `ticketoo`; REST namespace `ticketoo/v1`; cap `ticketoo_manage_tickets`; role `ticketoo_agent`.
- Statuses (strings): `open`, `pending`, `answered`, `closed` — extendable via filter `ticketoo_statuses`.
- No build step, no runtime Composer vendor (Composer/PHPCS are dev-only, installed inside the container).
- All SQL through `$wpdb->prepare`; all output escaped (`esc_html`, `esc_url`, `wp_kses_post` for message bodies).
- Options: `ticketoo_auto_close_days` (int, default 14, 0 = off), `ticketoo_attachment_max_mb` (int, default 5), `ticketoo_attachment_types` (CSV, default `jpg,jpeg,png,gif,pdf,zip,txt,docx`), `ticketoo_from_name`, `ticketoo_from_email`, `ticketoo_allow_guests` (bool, default 1), `ticketoo_counter_refresh_seconds` (int, default 60).
- Tests run only inside the container: `npx wp-env run cli --env-cwd=wp-content/plugins/ticketoo <cmd>`.
- Plugin header exactly as in spec §3 (Plugin URI = GitHub repo, Author = Iman Shadmehri, Author URI = https://elinweb.ir).

## Review Focus

Failure modes the spec implies but that no single feature test covers; each has a pinning test in the owning task.

1. **Forged/wrong guest token** must yield 403, never ticket data — pinned in Task 5 (`test_guest_wrong_token_is_forbidden`) and Task 6 (`test_download_wrong_token_forbidden`).
2. **IDOR — authenticated user touching another user's ticket** must yield 404/403 — pinned in Task 5 (`test_user_cannot_read_foreign_ticket`) and Task 6 (`test_user_cannot_close_foreign_ticket`).
3. **Dangerous upload (PHP payload, spoofed extension)** must be rejected, not stored — pinned in Task 6 (`test_upload_rejects_disallowed_type`).
4. **Auto-close must not touch `answered` tickets** (spec: only `open`/`pending`) — pinned in Task 13 (`test_sweep_ignores_answered`).
5. **Email to the person who caused it** must be suppressed — pinned in Task 12 (`test_no_email_to_replier`).
6. **Unauthenticated `scope=all`** must be refused — pinned in Task 5 (`test_list_scope_all_requires_capability`).
